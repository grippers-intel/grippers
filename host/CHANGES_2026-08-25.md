# 2026-08-25 ~ 08-26 작업 내역

`run_mission.py` 계열 코드에 진행한 수정/추가 사항 정리. 팀원 인수인계용.

## 1. 카메라/실행 안정화

- **`geti_detector.py`**: `GetiWorker` 두 개가 `Deployment` 인스턴스 하나를 공유하면서
  `Infer Request is busy` 오류가 나던 버그 수정 — 카메라(워커)마다 `load_deployment()`를
  따로 호출해서 각자 자기 `Deployment`를 갖게 함 (`run_mission.py`, `run_localize.py` 호출부도 변경).
- **`geti_detector.py`**: geti 추론이 쉬지 않고 계속 돌면(카메라 1대 ~0.8초+) 메인 루프
  (카메라 캡처+ArUco+화면 갱신)가 CPU를 못 받아 실측 1.7Hz까지 느려지던 문제 — 워커가
  실제로 다시 추론하기까지 최소 간격(`mission_config.GETI_INFER_INTERVAL_S`=0.3초)을 두도록
  스로틀링 추가. 그 사이 새 프레임은 최신 것만 남기고 버림(기물은 안 움직이므로 무방).
  실측 0.3초부터 메인 루프가 8Hz대로 거의 회복.
- **`run_localize.py`, `run_mission.py`**: `cv2.namedWindow(..., cv2.WINDOW_NORMAL)`로 카메라
  원본 창 크기조절 가능하게 함.
- 카메라 인덱스 이슈: 노트북 내장캠(0) 대신 C920 두 대(1, 2) 사용하도록 확인. 카메라 두 대를
  동시에 열 때 USB 대역폭/포트 문제로 간헐적으로 안 열리는 현상 발견 — 물리 포트를 바꿔서 해결.
  (코드 문제 아님, 하드웨어/USB 토폴로지 이슈)

## 2. `piece_map.py` — `PieceTracker` 신규 추가

기존 `merge_observations()`(매 프레임 독립 계산)의 한계를 보완하는 프레임 간 추적기:

- **위치 기반 매칭**: 라벨이 아니라 좌표로 같은 기물인지 판단 → 한 프레임 오분류가 유령
  기물을 안 만듦.
- **라벨 다수결**: 트랙마다 최근 라벨들의 confidence 가중치를 누적, 감쇠(`PIECE_LABEL_DECAY`)
  시키며 다수결로 확정 라벨 결정.
- **hold**: `PIECE_HOLD_SEC` 동안 관측이 없어도 트랙 유지 (카메라 한쪽만 봐도 안 사라짐).
- **확정 지연**: 생긴 지 `PIECE_CONFIRM_SEC` 지나야 출력에 반영 — 한 프레임짜리 오검출이
  잠깐이라도 화면에 안 찍히게 함.
- **라벨당 최대 개수**: `PIECE_MAX_PER_LABEL`(=2)개 넘으면 점수 낮은 트랙은 출력에서 제외
  (상태는 유지, 다시 강해지면 복귀 가능).
- `PieceTracker.reset()` 추가 (LiveMap 리셋 버튼용).

## 3. `live_map.py` — 신규 파일: 2D 탑뷰 라이브 지도

카메라 원본 대신 로봇/기물/상자를 단순 도형으로 그리는 GUI (matplotlib, 논블로킹).

- 로봇: 방향 화살표 + 충돌반경(`ROBOT_RADIUS_M`) 점선 원
- 기물: 라벨별 전용 아이콘 (star=✩, soccer=❆, box=흰 네모, 체스말(queen/knight/rook)=
  유니코드 체스 기호) — DejaVu Sans 폰트에 실제로 있는 기호만 사용
- 상자(toy/chess): 고정 위치 사각형
- 경로선: 로봇 → (회피 경유점) → (ㄱ자 모서리) → 목표, 매 사이클 갱신
- 작업 영역(`WORKSPACE_X` x `WORKSPACE_Y`) 밖 관측은 화면 표시·타겟 선정 둘 다에서 제외
  (물리적으로 있을 수 없는 자리의 오검출 필터링)
- 범례: 로봇/경로/기물 6종, 줄 간격 넓힘(`labelspacing`), 우측에 현재 개수(`xN`) 표시,
  맨 아래 `Total: N` — 텍스트는 매 프레임 갱신(박스 크기는 초기 최대폭 기준으로 고정해서
  글자 길어져도 안 잘리게 함)
- 상태 텍스트: 프레임 번호, pose, 미션 state, 다루는 라벨, 실제 전송한 명령(`cmd`,
  fsm.last_cmd), pieces 개수
- 버튼 4종:
  - **Reset**: 화면 + `PieceTracker` + `MissionFSM` 상태 초기화
  - **Mode (AUTO/MANUAL)**: 자동↔수동 전환 (+ 리셋)
  - **Prev / Next**: 수동 모드에서 상태 전이를 한 단계씩 수동 진행(칸을 반씩 나눠 배치).
    Next 옆 표시등이 전이 조건 충족 시 초록, 아니면 빨강(회색=로봇 못 찾음). Prev는
    GRASP/PLACE/FACE_BOX를 포함해 한 단계씩 되돌림(SEARCH_TARGET까지 가면 target/dest도 잊음)

## 4. `mission.py` — 미션 FSM 재설계

- **라벨 고정 제거**: `--target`/`--dest` 없이, 매 `SEARCH_TARGET` 사이클마다 "현재 로봇
  위치에서 가장 가까운 기물"을 라벨 무관하게 선택 (`WORKSPACE_X` x `WORKSPACE_Y` 안의
  기물만 후보 — 상자 자리 및 물리적으로 있을 수 없는 x좌표는 제외).
- **목적지 자동 결정**: `mission_config.PIECE_DEST_BOX`로 라벨→상자 자동 매핑
  (체스말→chess, 나머지→toy).
- **연속 반복**: 하나 내려놓고 끝나지 않고 다시 `SEARCH_TARGET`으로 — 작업 영역에 기물이
  없어질 때까지 반복. 상자 자리에 내려놓은 기물은 후보에서 자동 제외(재파지 방지).
- **상자 앞 정지**: 목적지 좌표를 상자 "중심"이 아니라 앞(작업영역 쪽으로
  `BOX_L/2 + BOX_APPROACH_MARGIN_M`만큼 뗀 지점)으로 변경.
- **새 상태 `FACE_BOX`**: `CARRY_TO_DEST` 완료 후 곧바로 `PLACE`로 안 넘어가고, 먼저
  정해진 방향(`BOX_FACE_YAW_DEG`=90°, map 기준 "12시"/+y 방향)으로 제자리 회전해서 맞춘
  뒤 `PLACE`로 진입 — 항상 같은 방향(상자 정면)을 보고 내려놓게 하기 위함.
- **수동 모드**: `manual_mode`, `ready_to_advance`, `request_advance()`(Next),
  `request_back()`(Prev, GRASP/FACE_BOX/PLACE 포함 전 상태로), `set_manual_mode()`(Mode
  버튼) — LiveMap 버튼과 연동.
- **경로 시각화용 상태 노출**: `nav_goal`, `nav_corner`, `last_nav`, `last_cmd`(실제
  전송한 "go"/"stop"/"yaw+"/"yaw-") — LiveMap이 이걸로 경로선/상태 텍스트를 그림.

## 5. `navigator.py` — 축정렬 주행 + 직진/정지/회전 상태머신

차량이 사선 이동 없이 항상 x축/y축 정렬로만 달리고, 회전은 -90/90/180도 단위로만 하도록
재설계 (기존 대각선 최단거리 방식에서 변경).

- **`DriveSequencer`**: `FORWARD`/`STOP`/`ROTATE` 3개 모드를 관리하는 상태머신.
  목표 방위각과 오차(`DRIVE_YAW_TOLERANCE_DEG`=5도)를 벗어나면 `STOP`(전이 신호 1사이클)
  → `ROTATE` → 정렬되면 다시 `STOP` → `FORWARD`.
- **`AxisPathPlanner`**: 로봇→목표 직선 대신, 한 축을 먼저 목표 좌표까지 맞추고
  (`AXIS_LEG_TOLERANCE_M`=3cm 이내면 완료로 판정) 나머지 축으로 넘어가는 "ㄱ자" 경로 계산.
  어느 축을 먼저 갈지는 로봇 현재 yaw에서 회전이 더 적게 드는 쪽(동률이면 x축 우선).
- **회피 버그 수정**: 처음엔 기존 `next_waypoint()`의 "경로에 수직으로 비켜가기" 로직을
  그대로 재사용했는데, 그 우회점이 장애물 위치 기준으로 고정돼서 로봇→우회점 방향이
  축정렬을 안 지키는 사선이 되는 버그가 실측으로 발견됨(`target_yaw=109.4°`처럼 90도
  단위가 아닌 값 발생). `AxisPathPlanner` 안에 `_axis_bypass()`를 새로 만들어, 항상
  "로봇의 지금 좌표"를 기준으로 이동 중인 축은 그대로 두고 다른 축 좌표만 바꾼 우회점을
  내도록 수정 — 회피 중에도 항상 순수 축 방향 이동 유지.

## 6. `vehicle_link.py` + 통신 규격 — Pi 실전 연동용 UDP 구현체 추가

- **`MissionCommand` 필드 재설계**: 기존 `mode`(FORWARD/STOP/ROTATE) 방식에서
  `cmd`("go"/"stop"/"yaw+"/"yaw-") + `status`(미션 단계 이름, 예: APPROACH_PIECE/GRASP/
  FACE_BOX/PLACE) 두 필드로 분리. 차량 쪽은 회전 방향까지 Host가 이미 정해서 보내주므로
  각도 계산을 전혀 할 필요가 없음 — `yaw_error_deg` 부호 그대로 `yaw+`/`yaw-`를 결정.
- **`UdpVehicleLink` 신규 클래스**: UDP(포트 5005 명령 송신 / 5006 상태 수신) + JSON으로
  실제 차량과 통신하는 구현체. `run_mission.py --vehicle-ip <Pi IP>`로 활성화(안 주면 기존
  `ConsoleVehicleLink`).
- **`VEHICLE_LINK_PROTOCOL.md` 신규**: Host↔Pi 통신 규격 전체 문서(패킷 스키마, 동작 매핑,
  워치독 권장사항, 설계 이유).
- **`PI_BRIDGE_TASK.md` 신규**: Pi 쪽(또는 Pi와 통신하는 별도 컴퓨터) 담당자에게 그대로
  전달하는 작업 지시서 — Host PC 코드/맥락 몰라도 되게 필요한 내용만 압축.
- **`pi_udp_bridge.py` 신규**: Pi 쪽 UDP 리스너 뼈대 스크립트. 실제 모터 제어/SmolVLA 호출은
  `_do_grasp()`/`_do_place()`/`_handle_cmd()` 안에 채워 넣을 자리만 마련. GRASP/PLACE는
  별도 스레드로 돌려서 그 사이에도 명령 수신·워치독이 안 끊기게 처리, 자체 워치독 로직
  포함(`--watchdog-sec`).

## 참고 — 아직 해결 안 된 것

- 캘리브레이션 미실시 상태 (`calib/cam*.npz` 없음) — HFOV 근사값 사용 중이라 화면 가장자리
  오차 큼. `aruco/calibrate_camera.py`로 카메라별 실측 필요 (팀원 PC 진행 예정, 카메라가
  물리적으로 연결된 PC에서만 가능 — 개체차 있어서 다른 카메라 캘리브레이션 값은 못 씀).
- Pi 쪽 UDP 브릿지(`pi_udp_bridge.py`)는 아직 뼈대뿐 — 실제 모터 제어/SmolVLA 연동 필요.
- Prev 버튼으로 GRASP/PLACE를 넘어 되돌아가는 건 Host PC 쪽 상태만 되돌릴 뿐, 실제
  차량이 이미 한 물리적 동작(집기/놓기)을 취소하지는 않음.
