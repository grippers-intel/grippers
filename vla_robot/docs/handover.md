## 1. 지금 무엇이 되나

- **정리**: "모두 정리해줘" · "장난감만 정리해줘" 같은 지시(입력창·마이크) → Claude 가 대상 라벨로 해석 → 작업장 안 기물을 하나씩 집어 바구니에 넣는다.
- **건네기**: "룩 가져와" → 손이 보이면 손 앞으로 가서 ㄱ자 자세로 건넨다.
- **10-12 교육장 실기**: ACT 판 8번 모두 끝까지(6/6 ×4 · 2/2 ×2 · 5/5 · 1판은 사람이 2개 뒤 ESTOP), HALTED 없음.
  파지 첫 시도 성공은 대체로 6번 중 5~6번(빈손이면 위치를 다시 보고 한 번 더). 운반 41번 중 39번이 "회전 → 직진 → 회전 → 투입" 한 모양.

## 2. 하루 순서

1. **기동** — [pi_deploy.md §4](pi_deploy.md): Pi 켬 → 차체·팔 배터리 확인 → Pi 코드 갱신(`git fetch` / `checkout`) →
   `pi_preflight.sh --beep`(부저가 울려야 정상) → 스택(**소스 경로 런치**, `config:=…/robot.yaml`) → 노트북에서 run_host:
   ```powershell
   cd vla_robot\host
   .venv\Scripts\python.exe run_host.py --pi-ip 192.168.0.7 --mode instructed
   ```
   시작 줄 `검출기: geti · GPU.0` · 시연 UI http://127.0.0.1:8765/ · 로봇 마커를 카메라 2대가 보면(`cams=2`) 좋다.
2. **판 돌리기** — 지시를 넣는다. 오래 쉬었다 시작하면 로봇이 6 s 쯤 서 있다 출발한다(정상 — 아래 4).
3. **마무리** — [pi_deploy.md "하루 마무리"](pi_deploy.md): 로그 PC 저장 → Hailo 사용 0 → 스택 SIGINT(노드 6개 `finished cleanly`) →
   `docker stop IntelPi` → `ssh -t pi@192.168.0.7 'sync && sudo shutdown -h now'`.

## 4. 늘 일어나는 일 (고장 아님)

- **컨트롤러 재기동**: Pi 가 예정대로 차체 컨트롤러를 다시 띄운다 — 스택 기동 직후 · 팔 작업 시작 때(회전 뒤 바퀴 울음 정리) ·
  **오래(60 s 넘게) 서 있다 첫 출발 전**(보드가 오래 쉬면 첫 명령을 안 받던 무응답을 막는다). 화면 알림은 없고 몇 초 서 있다 이어 간다.
  Host 가 무응답·폭주를 보고 요청한 복구만 "차체 컨트롤러를 다시 띄우는 중입니다" 알림이 뜬다.
- **바구니 앞 기물 먼저**: 다음 기물을 들고 가면 바구니 앞에 설 자리가 없을 때만 그 자리를 막는 기물부터 잡는다.
  거리가 5 cm 안으로 비슷하면 정차 구역에 가까운 기물부터. 로그에 이유가 남는다.
- **`쥔 기물로 본다: …` 로그**: 쥔 기물이 탑뷰에서 다른 라벨로 보인 것을 장애물에서 뺐다는 뜻.
- **바구니 안 기물이 화면에 보임**: 정리 완료 표시다. 대상이 아니다.

## 6. 알려진 한계

- **DP 보류**: 같은 날 파지 43 %(ACT 86 %), 노트북 발열 증가. 원인 후보(샘플링 10회 · 관측 2프레임 복제 · 청크 63)와 다시 할 순서는
  Obsidian `결정/파지 정책은 ACT 유지, DP 는 보류` 와 아티팩트 "DP 파지 개선 과제".
- **유령 필터의 절충**: 쥔 동안 로봇 40 cm 안에 나타난 "처음 보는" 검출은 쥔 기물로 보고 피하지 않는다. 다가가는 동안 한 번도 안 보인
  실제 기물이나 8 cm 넘게 밀린 기물이 거기 있으면 놓칠 수 있다.
- **재기동 직후 무응답**: 드물게(재기동 5 s 뒤 27번 중 1번) 남는다 — Host 자동 복구(약 13 s)가 처리한다. 근본 원인은 보드 펌웨어 쪽으로 추정.
- **회전 중 ESTOP**: 관성으로 7° 더 돌아 "ESTOP 인데 돈다" 폭주로 보고 보드 리셋을 한 번 요청한다(무해).
- **시뮬의 꺾이는 운반**: 시뮬은 짧은 회전 뒤 흐름을 실제보다 크게 봐서 꺾이는 운반이 실기(95 % 한 모양)보다 많이 나온다 — 비교용으로만 읽는다.
- **Host CPU**: 검출을 내장 그래픽으로 옮겨 대기 11 % · 작업 19 %(16스레드 기준). 남은 몫은 카메라·ArUco.
