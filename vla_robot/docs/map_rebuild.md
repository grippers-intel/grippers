# 맵 재구축 절차

세트장을 다시 만들 때 순서대로 한 번씩 하면 `host/config/host.yaml` 이 실물과 맞는다.
값을 손으로 옮겨 적는 단계를 최소로 두는 것이 목적이다 — 예전에 값이 파이썬 상수로
흩어져 있어 한쪽만 고쳐지는 일이 잦았다.

## 0. 확정된 것 (2026-09-29, 장판 실측 반영)

| 항목 | 값 | 비고 |
|---|---|---|
| 바닥 | **장판 1.835 × 2.050 m** (실측, 자르지 않는다) | 학습 때와 비슷한 색. 2.050 m 쪽이 카메라 방향(앞뒤). 배송 규격은 2.000 이었다 |
| 작업 경계 | **장판 가장자리** — `wall_x [-0.0175, 1.8175]` · `wall_y [-0.125, 1.925]` | 가벽 없음. 경로계획기가 여기서 로봇 반경을 뺀다 |
| 좌표계 | 1.8 m 설계 사각형을 장판 **가운데** 둔 기준 | 원점은 장판 안쪽의 한 점일 뿐 — 바닥에 표시할 필요 없다 |
| 바닥 마커 | 1 (0.100, 0.400) · 2 (1.700, 0.400) · 3 (0.100, 1.400) · 4 (1.700, 1.400) · 120 mm | 카메라당 4장이 보이는 자리. 모서리에 두면 2장만 보인다(아래 "왜") |
| 탑뷰 카메라 | **C920 2대** | 캘리브레이션 `host/calib/cam0·cam1.npz` (2026-09-14, rms 0.39/0.41) |
| 목적지 상자 | toy (0.450, 1.625) · chess (1.350, 1.625) · 210 × 350 × 220 mm | 긴 변 0.35 가 y 와 나란함 |
| 기물 | 40 mm 로 출력 완료 | |

이 값들은 이미 `host.yaml` 에 들어 있다. **아래대로 놓으면 설정은 고칠 것이 없다.**

## 1. 장판을 깐다

- **2.050 m 쪽을 카메라 방향(앞뒤)**, 1.835 m 쪽을 좌우로 둔다.
- 가장자리를 **테이프로 바닥에 눌러 둔다.** 말려 온 장판은 가장자리가 들떠 메카넘 바퀴가
  걸리고, 팔이 기물을 집는 높이도 달라진다.
- 실제 크기를 재 둔다. 배송 규격과 몇 mm 달라도 아래 계산기에 그 값을 넣으면 된다.

## 2. 마커·상자 놓을 자리를 계산한다

```
python tools/make_layout.py --mat 183.5 205     # 장판 실측 가로·세로(cm)
```

실측(1.835 × 2.050) 결과는 이렇다 — **모든 거리가 장판 가장자리 기준**이다.

| 무엇 | 어디에 |
|---|---|
| 마커 4장(중심) | **옆 가장자리에서 11.75 cm · 앞/뒤 가장자리에서 52.5 cm** (네 장 모두 같다) |
| toy 상자 | 왼쪽 모서리가 장판 왼쪽 끝에서 36.25 cm · 뒷면이 장판 뒤끝에서 **12.5 cm** |
| chess 상자 | 왼쪽 모서리가 장판 왼쪽 끝에서 126.25 cm · 뒷면이 장판 뒤끝에서 **12.5 cm** |

실측이 다르면 계산기가 새 `wall_x/wall_y` 도 같이 내 준다 — 그걸 `host.yaml` 에 넣는다.

## 3. 바닥 마커를 붙인다

인쇄물은 **윗변이 +y(상자 쪽)를 향하게** 붙인다. 코너 순서가 그 전제로 짜여 있다.
붙이기 전에 **마커 크기가 120 mm 인지** 잰다(검은 사각형 바깥 변, 흰 여백 제외).
인쇄 배율이 다르면 외부파라미터가 그 비율만큼 틀어진다.

## 4. 카메라를 세운다

카메라는 **장판 앞/뒤 가장자리 가운데**(x = 0.9 m)에 서로 마주 보게 세운다.

```
python tools/check_coverage.py --sweep
```

| 배치 (장판 가장자리 기준) | 바닥 마커 | 한 대 이상 | 두 대 | 40 mm 기물 |
|---|---|---|---|---|
| **높이 1.60 m · 하향 57.4°** | 각 4/4 (46~70 px) | 100 % | **100 %** | **16.3 px** |
| 높이 1.70 m · 하향 58.9° | 각 4/4 | 100 % | 100 % | 16.0 px |
| 높이 1.50 m | 각 4/4 (47~74 px) | 100 % | 99 % | 16.6 px |

하향각은 각도기로 맞추지 말고 **화면 중앙에 작업 구역 중심이 오도록** 맞추면 그 값이 된다.
두 대 이중 관측 100 % 는 작업 구역 어디서든 두 카메라가 로봇 마커를 본다는 뜻이다.

## 5. 마커 확인

```
python tools/place_markers.py
```

- 카메라마다 바닥 마커 **4/4**
- **재투영오차 1 px 미만(GOOD)** — 2 px 를 넘으면 붙인 위치가 설정과 다르다
- 로봇을 올려 두면 ROBOT 행이 BOTH

위치가 어긋났으면 실측값을 넣어 좌표를 다시 만든다(cm).

```
python tools/make_layout.py --m1 10 40 --m2 170 40 --m3 10 140 --m4 170 140
```

⚠️ `--m` 모드의 좌표는 **1.8 m 설계 사각형 원점** 기준이다. 장판 **왼쪽·앞 가장자리**에서
잰 값이면 여백을 빼서 넣는다 — x 는 1.75 cm, y 는 12.5 cm. 예) 왼쪽에서 11.9 · 앞에서 52.8 이면
`--m1 10.15 40.3`.

## 6. 측위 품질을 잰다

로봇을 작업 구역 가운데 세워 두고 `python tools/check_localization.py --seconds 20`.

| 값 | 기준 |
|---|---|
| 재투영오차 | < 1 px |
| 위치 흔들림 | < 5 mm |
| yaw 흔들림 | < 1.0° |
| 놓침 비율 | 0 % |
| 관측 카메라 | 2 대 |

## 7. yaw 보정값을 잰다

상판 마커가 차체 정면과 이루는 각이다. 틀리면 **좌우로 흔들리며 앞으로 간다**.

```
python tools/calib_yaw.py --drive --pi 192.168.0.7      # 추천. 앞이 트인 곳에서
python tools/calib_yaw.py --facing x                    # 차가 못 움직일 때. 두 축을 다 잰다
```

나온 값을 `host.yaml` 의 `aruco.yaw_offset_deg` 에 적는다(지금 85.7 은 2026-09-06 정지 측정값).

⚠️ 로봇 마커는 **팔에 붙어 있다.** 팔이 idle 일 때만 이 보정이 유효하다 — 주행 중에는 항상
idle 이라 괜찮지만, carry 자세를 따로 교시하면 다시 재야 한다.

## 8. 마지막으로 전체를 한 번

```
python run_host.py            # 지도 화면에서 pose·경로·상자 목표가 맞는지
```

그다음이 `place.base_yaw_deg` 재측정(Host 가 실제로 정차시킨 자리에서)과 전체 사이클이다.

## 왜 마커를 장판 모서리에 두지 않나

가벽이 있을 때 마커를 안쪽에 둔 건 벽 근처 회전 위험 때문이었고, 그 이유는 사라졌다.
그래서 "마커가 곧 작업 경계"가 되도록 모서리에 두는 안을 계산해 봤다(2026-09-29).

| 배치 | 카메라당 보이는 마커 | 40 mm 기물 |
|---|---|---|
| 안쪽 마커 · 높이 1.70 m | **4장** | 17 px |
| 모서리 마커 · 높이 1.70 m | **2장**(먼 쪽만) | 17 px |
| 모서리 4장이 다 보이는 최선 | 4장 | **13 px** (높이 **2.6 m** 필요) |

가까운 쪽 모서리가 카메라 바로 아래·옆이라 화각 밖으로 빠진다. 팀 배치도 Rev.II 도 같은
이유로 접었다("네 모서리 ArUco 미채택, 후퇴 1.20 m 필요").

그런데 "마커가 경계를 정한다"는 모서리가 아니어도 성립한다. 마커가 장판에 붙는 순간
좌표계가 장판에 고정되고, 장판 가장자리는 그 좌표계에서 고정된 숫자가 된다. 그래서
**마커는 카메라가 잘 보는 안쪽에, 경계는 설정에서 장판 가장자리로** 나눴다.

## 왜 도구를 따로 두었나

`hardware/ArUco/` 에도 팀원이 만든 배치·좌표 도구가 있다. 그쪽은 **자기 `config.py`** 를
읽는다 — 그 값들이 서로 맞는지는 보여 주지만, 우리 Host 가 주행할 때 쓰는 값이 맞는지는
보여 주지 않는다. 실제로 두 설정이 갈려 있었다(마커 x 1.710 vs 1.700 · yaw 90.0 vs 85.7 ·
`cam0.npz` 가 세 벌). 여기 도구는 전부 `host.yaml` 하나만 읽는다.
