# 맵 재구축 절차

세트장을 다시 만들 때 순서대로 한 번씩 하면 `host/config/host.yaml` 이 실물과 맞는다.
값을 손으로 옮겨 적는 단계를 최소로 두는 것이 목적이다 — 예전에 값이 파이썬 상수로
흩어져 있어 한쪽만 고쳐지는 일이 잦았다.

## 0. 확정된 것 (2026-09-23)

| 항목 | 값 | 비고 |
|---|---|---|
| 작업장 | **1.800 × 1.800 m 정사각** | **가벽 없이** 만든다. 가벽을 쓰면 한 변이 1.810 이 된다 |
| 바닥 마커 | 1 (0.100, 0.400) · 2 (1.700, 0.400) · 3 (0.100, 1.400) · 4 (1.700, 1.400) | 새로 출력해 둠. 세트장 만들면서 붙인다 |
| 탑뷰 카메라 | **C920 2대** | 캘리브레이션은 `host/calib/cam0·cam1.npz` (2026-09-14, rms 0.39/0.41) |
| 목적지 상자 | toy (0.450, 1.625) · chess (1.350, 1.625) · 210 × 350 × 220 mm | 긴 변 0.35 가 y 와 나란하고 뒷면이 벽선에 밀착 |
| 기물 | 40 mm 로 출력 완료 | 검출 하한 37.4 mm 위 |

이 값들은 이미 `host.yaml` 에 들어 있다. **세트장을 그대로 만들면 설정은 고칠 것이 없다.**

## 1. 카메라를 세운다

가벽이 없으므로 근거리 가림이 사라져 예전보다 낫게 세울 수 있다. 계산 결과는 이렇다.

```
python tools/check_coverage.py --sweep
```

| 배치 | 바닥 마커 | 한 대 이상 | 두 대 | 최악 mm/px |
|---|---|---|---|---|
| **높이 1.70 m · 후퇴 0 · 하향 62.1°** | 각 4/4 | 100 % | **100 %** | 2.34 (40 mm = 17.1 px) |
| 높이 1.30 m · 후퇴 0 · 하향 55.3° | 각 3/4 | 100 % | 88 % | — |

좌우는 두 대 모두 x = 0.9 m(변의 중앙), 서로 마주 본다. 하향각은 작업 구역 중심을
겨누면 자동으로 그 값이 된다 — 각도기로 맞추지 말고 **화면 중앙에 작업 구역 중심이
오도록** 맞추면 된다.

> 두 대 이중 관측이 100 % 라는 것은 작업 구역 어디서든 두 카메라가 로봇 마커를 본다는
> 뜻이다. pose 가 한 대에 의존하지 않으므로 위치추정이 눈에 띄게 안정된다.

## 2. 바닥 마커를 붙인다

인쇄물은 **윗변이 +y(상자 쪽)를 향하게** 붙인다. 코너 순서가 그 전제로 짜여 있다.

```
python tools/place_markers.py
```

STATUS 창에서 확인할 것:

- 카메라마다 바닥 마커가 `min_floor_markers`(2) 이상 — 위 배치면 4/4 가 나온다
- **재투영오차 1 px 미만(GOOD)** — 2 px 를 넘으면 붙인 위치가 설정과 다르다는 뜻이다
- 로봇을 올려 두면 ROBOT 행이 BOTH 로 뜬다

붙인 자리가 계획과 다르면 줄자 값을 그대로 넣어 좌표를 다시 만든다(단위는 cm).

```
python tools/make_layout.py --x1 10 --y1 40 --width 160 --depth 100
python tools/make_layout.py --m1 10 40 --m2 170 40 --m3 10 140 --m4 170 140   # 네 점 각각
```

출력된 YAML 블록을 `host.yaml` 의 `aruco.floor_markers` 에 붙여 넣고 1번을 다시 본다.

## 3. 측위 품질을 잰다

로봇을 작업 구역 가운데 세워 두고,

```
python tools/check_localization.py --seconds 20
```

| 값 | 기준 |
|---|---|
| 재투영오차 | < 1 px |
| 위치 흔들림 | < 5 mm |
| yaw 흔들림 | < 1.0° |
| 놓침 비율 | 0 % |
| 관측 카메라 | 2 대 |

## 4. yaw 보정값을 잰다

상판 마커가 차체 정면과 이루는 각이다. 틀리면 **좌우로 흔들리며 앞으로 간다**.

```
python tools/calib_yaw.py --drive --pi 192.168.0.7      # 추천. 앞이 트인 곳에서
python tools/calib_yaw.py --facing x                    # 차가 못 움직일 때. 두 축을 다 잰다
```

나온 값을 `host.yaml` 의 `aruco.yaw_offset_deg` 에 적는다(지금 85.7 은 2026-09-06 정지 측정값).

## 5. 마지막으로 전체를 한 번

```
python run_host.py            # 지도 화면에서 pose·경로·상자 목표가 맞는지
```

그다음이 차체 기동 시험(`use_base:=true`)과 `place.base_yaw_deg` 재측정이다.

## 왜 도구를 따로 두었나

`hardware/ArUco/` 에도 팀원이 만든 배치·좌표 도구가 있다. 그쪽은 **자기 `config.py`** 를
읽는다 — 그 값들이 서로 맞는지는 보여 주지만, 우리 Host 가 주행할 때 쓰는 값이 맞는지는
보여 주지 않는다. 실제로 두 설정이 갈려 있었다(마커 x 1.710 vs 1.700 · yaw 90.0 vs 85.7 ·
`cam0.npz` 가 세 벌). 여기 도구는 전부 `host.yaml` 하나만 읽는다.
