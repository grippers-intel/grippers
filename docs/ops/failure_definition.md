## 0. 왜 필요한가

이전 주제의 FSM은 **선형**이었습니다. 어느 단계에서 실패하든 미션이 끝났으므로
"실패 1건"의 경계가 자명했습니다 — 미션 1회 = 시행 1회 = 성공 아니면 실패.

새 FSM은 **루프**입니다 ([`state_machine.md` §5](../design/state_machine.md)).
실패는 미션 종료가 아니라 `SCAN` 복귀 + 보류 목록(`held_ids`) 등록입니다.
`*FailedState` 4종이 삭제됐고, 미션 1회 안에서 물체 여러 개가 각각 성공·실패합니다.

그래서 계수 규칙을 문장으로 못박지 않으면 아래가 전부 사람마다 다르게 집계됩니다.

| 모호한 상황 | 정하지 않으면 |
|---|---|
| `GRASP` 를 2번 실패하고 3번째에 성공 | 실패 2건? 성공 1건? |
| `REJECT` 로 판정해 안전하게 내려놓음 | 설계대로 동작했는데 실패인가? |
| 가림 때문에 이번 사이클에 못 봤고 다음 사이클에 처리됨 | 실패인가? |
| 60초를 넘겼지만 결국 상자에 넣음 | 성공인가? |
| 측정 중 서보가 고장남 | 분모에 넣는가? |

**같은 시연 영상을 두 사람이 세면 같은 숫자가 나와야 합니다.** 이 문서의 목적은 그것뿐입니다.

## 1. 계수 단위 — 인스턴스

**인스턴스 = 물체 1개를 대상으로 한 정리 시도 1회.**

- 미션 1회(`IDLE` → `DONE`)는 인스턴스 여러 개를 포함합니다
- Results 표의 "정리 완료율 (20 인스턴스)" 가 이 단위입니다
- 접촉(F3)·오실행(F5)만 인스턴스와 무관하게 **사건 단위**로 누적합니다

> [!NOTE]
> 인스턴스의 시작은 `SELECT` 가 대상을 확정한 순간이고, 끝은 `INSERT`/`HANDOVER` 성공
> 또는 그 대상이 `held_ids` 에 등록되며 `SCAN` 으로 복귀한 순간입니다.
> **한 물체가 보류됐다가 다음 사이클에 재선택되면 인스턴스가 하나 더 생깁니다.**
> 정리 완료율의 분모는 인스턴스가 아니라 **배치된 물체 개수**입니다 (§5 참고).

## 2. 실패 6종

| 코드 | 이름 | 단위 | 판정 |
|---|---|---|---|
| **F1** | 미정리 | 물체 | 미션 종료 시점에 배정 상자에 들어가지 않음 |
| **F2** | 오배치 | 물체 | 규칙과 다른 상자에 들어감 |
| **F3** | 접촉 | 사건 | 가구·상자·벽·사람과 물리적으로 닿음 |
| **F4** | 시간 초과 | 인스턴스 | 인스턴스 사이클 시간 > 60초 |
| **F5** | 오실행 | 사건 | 명령하지 않은 동작을 개시 |
| **F6** | 사람 개입 | 물체 | 운영자가 로봇·물체·상자에 손을 댐 |

### F1 · 미정리

미션이 `DONE` 에 도달한 시점에 대상 물체가 배정된 상자 안에 없으면 **원인을 불문하고** 1건입니다.
미검출·파지 실패·`REJECT`·보류 소진이 전부 여기로 모입니다.

원인은 실패 건수에 반영하지 않고 **태그로만 기록**합니다 — 지표를 원인별로 쪼개면
분모가 흔들려 비교가 불가능해집니다.

| 태그 | 의미 |
|---|---|
| `undetected` | `scan_floor()` 가 끝내 검출하지 못함 |
| `approach` | 도달 실패로 보류 |
| `grasp` | 재시도 소진으로 보류 |
| `reject` | `POSE_PLAN` 에서 해 구간 없음 |
| `transport` | 이송 중 낙하·이탈 |

### F2 · 오배치

물체가 상자에 들어갔으나 `placement_rule` 과 다른 색입니다. **F1과 배타적입니다** — 들어갔으므로.
목표는 0회이고, 기준선은 4색 무작위인 25%입니다.

### F3 · 접촉

로봇 본체·팔·파지물이 **가구·상자·벽·사람**과 닿으면 1건입니다. 인스턴스와 무관하게 누적합니다.

**접촉이 아닌 것:**

- 파지 대상 물체와의 접촉 (그게 임무입니다)
- 상자 투입 시 물체가 상자 입구 안쪽 벽에 스치는 것
- 바닥과의 정상 접촉

**판정 기준은 "상자·가구가 움직였는가"** 입니다. 육안 + 시연 영상으로 판정하고, 애매하면 접촉으로 셉니다.

### F4 · 시간 초과

인스턴스 사이클 시간이 60초를 넘으면 1건입니다. **F1과 독립입니다** — 65초 걸려서 성공해도 F4 1건이고 F1은 0건입니다.

- 시작: `SELECT` 가 대상을 확정한 순간
- 끝: `INSERT`/`HANDOVER` 성공, 또는 보류 등록 후 `SCAN` 복귀

### F5 · 오실행 (음성)

명령하지 않았는데 미션이 시작되거나, 명령과 다른 `mode`/`target_cls` 로 시작하면 1건입니다. 목표 0%입니다.

**복창(`confirm_phrase()`)으로 사용자가 정정한 경우는 오실행이 아닙니다.** 복창이 바로 그 방어선이고,
방어선이 동작한 것을 실패로 세면 방어선을 넣을 이유가 없어집니다. 단 **복창 정정 횟수는 별도로 기록**합니다.

### F6 · 사람 개입

운영자가 로봇·물체·상자에 손을 대면 그 물체는 **즉시 F1로 계상하고 그 인스턴스를 종료**합니다.
"조금만 도와주면 됐을 텐데"를 성공으로 세지 않기 위한 규칙입니다.

안전 목적의 E-STOP은 개입이지만 실패가 아니라 **무효**입니다 (§4).

## 3. 실패로 세지 않는 것

설계가 의도한 동작을 실패로 세면 지표가 설계를 벌주게 됩니다. 아래는 **전부 성공 또는 중립**입니다.

| 상황 | 판정 | 근거 |
|---|---|---|
| `GRASP` 재시도 2회 후 3회째 성공 (`MAX_GRASP_RETRY = 3`) | **성공** | 재시도는 설계된 복구 경로. 예산은 **대상 1개당**이며 `SELECT` 에서 리셋됩니다. 단 **재시도 횟수는 인스턴스별로 기록** |
| `SCAN` 재스캔 후 검출 성공 (`MAX_RESCAN = 3`) | **성공** | 일시적 오검출 대비가 설계 의도 |
| `REJECT` 판정 후 안전하게 내려놓기 성공 | **F1 1건만** | 투입은 못 했으나 접촉(F3)은 아님. 안전 동작이 정상 수행된 것 |
| `held_ids` 등록 자체 | **중립** | 미션 종료 시점에 미정리로 남으면 그때 F1 |
| 가림으로 이번 사이클에 못 본 물체를 다음 사이클에 처리 | **성공** | 이월은 루프 FSM의 정상 동작 |
| `SCAN` 무변화 감지로 `DONE` 조기 종료 | **중립** | 무한 루프 방어선. 남은 물체는 각각 F1 |
| `PERCEPTION_FAILED` 로 종료 (이슈 #194) | 🔴 **측정 회차에서 제외** | 관측을 못 한 회차다. 남은 물체를 F1 로 세면 파지가 아니라 센서 장애를 파지 지표가 떠안는다. **DONE 과 같은 칸에 넣지 말 것** — 그러려고 상태를 가른 것이다 |

> [!WARNING]
> 마지막 행은 **무변화 감지가 올바를 때만** 중립입니다. 현행 구현은 보류된 물체가 바닥에
> 남아 있다는 이유만으로 발동하므로(**이슈 #131**), 정리 가능한 물체가 남았는데도 종료됩니다.
>
> **#131 수정 전에는 물체 2개 이상 시나리오를 측정 회차로 집계하지 마세요.** 남은 물체를 F1로
> 세면 실패 원인이 파지가 아니라 종료 판정에 있는데도 지표가 파지를 벌주게 됩니다.
> 이건 §4의 무효 시행과 다릅니다 — 무효는 **시행 단위 · 사후 판정**이지만, 이건 회차를 돌리기
> 전에 이미 지표가 성립하지 않는다는 걸 아는 경우입니다.

> [!CAUTION]
> **재시도 성공을 성공으로 세는 대신 재시도 횟수를 반드시 남기세요.**
> "성공률 90%, 평균 재시도 2.8회" 와 "성공률 90%, 평균 재시도 0.1회" 는 완전히 다른 시스템인데
> 성공률만 보면 구분되지 않습니다.

## 4. 무효 시행 (void)

아래 사유로 중단된 시행은 **분모에서 제외**하되 횟수와 사유를 기록합니다.

| 사유 | 예 |
|---|---|
| 하드웨어 고장 | 서보·모터·케이블 파손 |
| 전원 | 배터리 소진, 전원 차단 |
| 네트워크 | 노드 통신 두절 (AP 격리 포함) |
| 안전 E-STOP | 사람·기물 보호 목적의 정지 |
| 측정자 실수 | 초기 배치 오류, 명령 오발화 |

**규칙 3가지:**

1. 무효는 **사전에 선언할 수 없습니다.** 시행 후 사유를 적어야 성립합니다
2. 무효 사유는 `measurements.md` 에 시행 번호와 함께 남깁니다
3. **한 회차의 무효율이 20%를 넘으면 그 회차 전체를 재측정합니다** — 무효가 많다는 것은
   측정 조건이 통제되지 않았다는 뜻이지 운이 나빴다는 뜻이 아닙니다

## 5. 지표 매핑

[`milestones.md` § Results](milestones.md#-results) 각 행이 위 정의로 어떻게 계산되는지입니다.

| 지표 | 목표 | 계산 |
|---|---|---|
| 정리 완료율 (20 인스턴스) | ≥ 90% | `(배치 물체 수 − F1) / 배치 물체 수` · 무효 시행 제외 |
| 오배치 횟수 | 0회 (기준선 25%) | F2 합계 |
| 가구·상자 접촉 | 0회 | F3 합계 |
| 물체당 사이클 시간 | ≤ 60초 | 인스턴스 사이클 시간 중앙값. **F4는 초과 건수** |
| 파지 성공률 (파지 그룹별) | *(M2)* | `GRASP` 진입 대비 부하 임계 통과 비율. 재시도 성공 포함 |
| FETCH 대상 정확도 | *(M2)* | `target_cls` 일치 인계 / FETCH 미션 수 |
| 음성 명령 인식률 | *(M2)* | `parse()` 성공 / 총 발화 수 |
| 오실행률 (음성) | 0% | `F5 / 총 발화 수` |
| 검출 추론 지연 | *(M2)* | `scan_floor()` 왕복 시간 p95 |

> 성공률은 시행 횟수와 **이항분포 95% 신뢰구간**을 병기합니다 ([`measurements.md` §0](measurements.md)).
> 20 인스턴스에서 90%는 신뢰구간이 68~99%로 넓습니다 — 숫자 하나만 쓰지 마세요.

## 6. 미확정 — M2 실측 후

| 항목 | 왜 지금 못 정하나 |
|---|---|
| **파지 그룹**의 정의 | 눕힌 기둥/세운 기둥/체스말로 나눌지, 크기로 나눌지는 A3 asset freeze 이후 |
| **60초** 기준의 타당성 | 실기 사이클 시간을 한 번도 측정하지 않았습니다. M2에서 재검토 |
| 음성 인식률의 **분모** | 발화 단위인지 명령 단위인지는 `grippers_vla` 구현 형태에 종속 |
| 검출 지연 **임계값** | Hailo 가속 여부(#6 DFC 호스트)에 따라 달라집니다 |

**3인 합의가 필요한 항목** — 이 문서에서 제가 정한 것 중 이견이 나올 수 있는 3가지입니다.

1. **재시도 성공을 성공으로 센다** (§3) — 엄격하게 갈 거면 "1회 시도 성공률"을 별도 지표로 추가
2. **F6 사람 개입 시 즉시 F1 + 인스턴스 종료** (§2) — 개입 후 재개를 허용할지
3. **무효율 20% 초과 시 회차 재측정** (§4) — 기준선 자체
