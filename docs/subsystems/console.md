# 관제 콘솔 — 노트북 GUI + 음성


> **설계 결정 (2026-08-13)** — 음성 입출력 모듈을 **로봇에 탑재하지 않고, 시연용 노트북에서 실행**합니다.
> 노트북은 GUI 관제 콘솔이자 음성 입력 장치를 겸합니다.

│   🖵  카메라 3종 · 검출 오버레이 · 상태 표시             │          │
│                                                        │          │

                       ROS 2 DDS (WiFi) — 텍스트만 전송  │

## 왜 로봇에 싣지 않는가

`voice_io` 는 **기존 명령 토픽에 텍스트를 발행하는 노드**일 뿐입니다. 이 노드가 Pi에서 도는지
노트북에서 도는지는 DDS 입장에서 투명하며, 따라서 이것은 **아키텍처 변경이 아니라 배포 위치 변경**입니다.

| 로봇 탑재 시 문제 | 노트북 실행으로 |
|---|---|
| USB 마이크·스피커 발주 필요 | **발주 항목 2개 소멸** |
| Pi 5에 3.5 mm 오디오 잭 없음 | 무관 |
| AI HAT+ 2가 PCIe + GPIO 스태킹 헤더 점유 → 오디오 HAT 간섭 | 무관 |
| **모터·서보 소음이 마이크를 덮음** | 마이크가 소음원에서 물리적으로 분리 |
| STT가 ROS2 7개 노드 + Hailo 파이프라인과 CPU 경합 | Pi CPU 예산 확보 |
| 푸시투토크 물리 버튼 배선 | **GUI 버튼** — 더 안정적, 배선 불필요 |
| Pi 성능 제약으로 Vosk가 1순위 | **whisper.cpp small 실용화** → 한국어 정확도 상승 |

> [!IMPORTANT]
> **이것이 Ports & Adapters의 가장 강한 증거입니다.** 입력 채널을 추가하고 그 **실행 위치를 로봇 밖으로 옮겼는데,
> `domain/` diff가 0줄입니다.** 발표에서 이 지점을 명시적으로 쓸 것.

## 설계 제약 3가지

**① 오디오를 ROS2로 흘리지 않습니다.** 노트북에서 **STT를 끝내고 텍스트만** 발행합니다.
오디오 스트림을 토픽으로 보내면 카메라 스트림과 대역폭을 경합하고, 명령 지연이 사이클 타임에 직접 들어옵니다.
텍스트만 보내면 대역폭은 사실상 0입니다.

**② 로봇에 남는 것과 노트북으로 가는 것을 명확히 구분합니다.**

| 노트북 | 로봇 (온보드) |
|---|---|
| STT (음성 → 텍스트) | **명령 해석** (`CommandInterpreter` → `MissionSpec`) |
| TTS (상태 → 음성) | **FSM 전체** (`mission_orchestrator`) |
| GUI 표시 · 텍스트 입력 · PTT 버튼 | **검출·분류** (Hailo-10H) |
| | **주행·파지 제어** |

**노트북에 있는 것은 STT 하나뿐**이며, 이는 키보드 드라이버와 같은 층위의 입력 장치입니다.
판단과 실행은 전부 로봇 위에서 돕니다.

**③ TTS는 관제 콘솔에서 나옵니다.** 로봇이 말하는 것이 아니라 **관제 콘솔이 로봇 상태를 음성으로 보고하는** 구조입니다.
GUI에 로봇 발화를 말풍선으로 병기해 어느 쪽이 말하는지 명확히 합니다.

## 복창·되묻기 흐름

```
"체스말 가져와"  →  "체스말을 가져올게요"  →  (확인)  →  실행
"그거 가져와"    →  "가베인가요, 체스말인가요?"  →  "체스말"  →  실행
"블로그는 파란…"  →  "다시 말씀해 주세요"   ← STT 오인식, 확인 없는 실행 경로 없음
```

기존 `CLARIFY` → `CORRECT` 문형이 그대로 음성 대화가 됩니다.
**비전공자가 가장 크게 반응하는 장면은 로봇이 되묻는 순간**이므로, 시연 시나리오에 반드시 포함합니다.

## 설계 판단

| 항목 | 결정 | 이유 |
|---|---|---|
| 푸시투토크 | ✅ GUI 버튼 | 시연장 오인식 방지 + 통제 |
| 웨이크워드 상시 대기 | ❌ 미채택 | 시연 통제, Stretch 등급 |
| 실행 전 복창 | ✅ **필수** | STT는 반드시 틀림 — 오실행률 0% 목표 |
| 텍스트 폴백 | ✅ 유지 | 음성만 되는 상태를 만들지 않음 |
| 클라우드 STT | ❌ 제외 | 시연장 인터넷 의존 |
| 오디오 토픽 전송 | ❌ 금지 | 대역폭 경합 (위 §설계 제약 ①) |

## 🔴 네트워크가 크리티컬 패스입니다

GUI 제어와 음성 명령이 모두 노트북에 있으므로, **DDS 통신이 끊기면 시연이 통째로 멈춥니다.**

가장 큰 함정은 **시연장 WiFi의 AP 격리(client isolation)** 입니다. 대부분의 기관 WiFi는 클라이언트 간
직접 통신을 차단하는데, 그러면 **DDS 디스커버리 자체가 되지 않아 노드가 서로 보이지 않습니다.**

| 대응 | 우선순위 |
|---|---|
| **전용 라우터 또는 로봇 핫스팟 지참** | 1순위 — 사실상 필수 |
| `ROS_DOMAIN_ID` 고정 · 팀 전체 공유 | 1순위 |
| M2에서 시연장 네트워크 실측 (`ros2 topic list` 교차 확인) | 1순위 |
| 유선 이더넷 폴백 경로 확보 | 2순위 |
| 영상은 `web_video_server` 압축·저해상도, 명령 토픽은 reliable QoS | 2순위 |

## GUI 우선순위

GUI를 **입력 채널**과 **관측 채널**로 분리해서 봅니다.

| 순서 | 항목 | 비용 | 시점 |
|---|---|---|---|
| 1 | **CLI 입력 스크립트** (`ros2 topic pub`) | 30분 | 즉시 — 없으면 M2에서 아무것도 못 돌림 |
| 2 | rqt/rviz 관측 조합 | 반나절 | M2 — 만드는 게 아니라 설정 |
| 3 | 노트북 웹 콘솔 (입력 + 관측) | 1~2일 | M3 |
| 4 | 음성 (STT+TTS) | **2~3일 · 발주 없음** | **8/30 판단** — 핵심 동작 성공 시 착수 |

- 카메라 보기 → `rqt_image_view`, 검출 오버레이 → rviz `MarkerArray`
- 웹 콘솔은 얇게: `web_video_server` + `<img>` + rosbridge 상태 텍스트

> **마이크 위치 주의** — 노트북 내장 마이크는 발표자가 노트북 앞에 있어야 인식됩니다.
> GUI 조작자 1명을 노트북에 고정하거나, USB 핀마이크를 노트북에 연결하세요 (로봇 탑재보다 훨씬 저렴·간단).

> **부수 효과** — 시연용 노트북이 **x86_64 Ubuntu라면 Hailo DFC 호스트로도 쓸 수 있습니다.**
> 미결 #6(DFC 호스트 확보)과 함께 확인할 것.
